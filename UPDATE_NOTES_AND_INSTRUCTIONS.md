### PDF: too much white space, round 1 (fixed)

**Issue reported:** "Ensure the PDF does not have too much white space."

**Root cause (two separate, compounding bugs found):**
1. Every individual PDF section is captured as its own separate image, wrapped in a fresh temporary container. That container was reusing the *whole-report* wrapper's styling — including its `padding:20px` meant to apply **once**, around the outside of the entire report. Since dozens of sections are each captured as their own container, that 20px top+bottom padding was being duplicated into every single one of them, adding up to a large amount of pure blank space across a multi-page export.
2. The font/padding shrinking pass (fixed in the round before this) only ever scaled **font-size** and **padding** — it never touched **margin**. This app's own styling leans on margin, not padding, for most of its spacing (section headings alone carry `margin: 35px 0 15px`). So text shrank correctly to 9pt but the margins around it stayed at their full original, un-shrunk size — text and whitespace fell wildly out of proportion, which reads as "too much white space" even though the page-packing itself was unchanged.

**Fix applied:**
- The per-section capture container no longer inherits the report-level padding; that padding is stripped out and explicitly zeroed for these containers instead.
- Added `display:flow-root` to each capture container so a cloned section's own margins are always fully and predictably contained within it (avoids relying on browser-specific CSS margin-collapse behavior between a container and its content).
- Margins are now captured and scaled by the same two-pass, per-element approach already used for font-size and padding — so a heading's spacing shrinks in the same proportion as its now-9pt text, instead of staying at its original, much larger size.

### PDF: font size too small / not Arial (fixed)

**Issue reported:** "The current font size used for the PDF export are too small. Resize the fonts to size 9 Arial font."

**Root cause:** The PDF export (`captureChunksIntoPdf` in `app.js`) previously shrank every exported element's font-size by a fixed **relative** multiplier (`FONT_SCALE = 0.35`). Because different elements start at very different sizes, a relative multiplier never actually converges on any specific point size.

**Fix applied:** Replaced the relative multiplier with an **absolute, computed target**: every exported text element is now set to the exact pixel size that corresponds to a true **9pt** font, with `font-family` forced to `Arial, Helvetica, sans-serif`.

3. Keep that window open while you use the app - it's the server itself running, not just a log. Closing it stops the server.
4. When you're done, close the window (or click inside it and press Ctrl+C).

Your existing data won't move or change either way - `http://localhost:8766/...` and `file:///C:/Users/roywl/Roach/Personal/Illuminate/index.html` are different browser storage origins, though, so the very first time you switch over, the app will look like a fresh install (no saved account) at the new address. If that happens and you'd like your existing account carried over, let me know before creating a new one and I can walk through exporting/reimporting your data, or add an in-app export/import feature if you'd use it more than once.
